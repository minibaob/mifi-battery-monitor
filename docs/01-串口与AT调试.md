# 01 · 串口与 AT 调试

## 1. 设备长什么样

插上 USB 后 Windows 会注册成**复合设备**：

```
USB\VID_1286&PID_4E3D
├── MI_00  RNDIS 网卡        （Web 管理页走这里，见 docs/02）
├── MI_02  串口 → COM4       （日志 / 诊断口）
└── MI_04  串口 → COM3       （AT 指令口）
```

两个口都是 115200 8N1、无流控。**顺序不固定**，换机器或换 USB 口可能反过来，所以不要写死 COM 号，用 VID/PID 枚举。

```bash
python scripts/asr_cli.py ports
```

## 2. 怎么确认哪个是 AT 口

发 `AT`，看有没有 `OK`。

| 端口 | 现象 | 判定 |
|---|---|---|
| COM3 | `AT` → `OK`，`ATI` → `ASR, Inc.` | AT 指令口 |
| COM4 | 打开瞬间有一批二进制日志，读空后**完全静默** | 日志口 |

日志口有个容易误判的特性：**只有打开那一刻的积压缓冲**，读完就再也没输出。所以"打开 COM4 看到一堆乱码"不代表它在持续刷日志，也不代表口是坏的。

## 3. 设备信息（实测）

```
AT+CGMI       → +CGMI: "ASR"
AT+CGMM       → +CGMM: "Nezha_MIFI"          ← 机型代号
AT+CGMR       → +CGMR: "1.057.064"           ← 固件版本
ATI           → ASR, Inc.
AT+CPAS       → +CPAS: 0                      ← 唯一还能用的查询类指令
```

Web 侧还能拿到更细的版本串：`LB12AKAS00160_N12_BD_M1261T_V009`（`LB12A` 硬件平台 / 客户代号 / `N12` 版本 / `M1261T` 机型 / `V009` 迭代），构建日期 `Dec 4 2025`，**单分区**（`two_partition=0`，没有 A/B 回滚，刷坏即砖）。

## 4. 电量指令探测矩阵

原则：**只发查询形式**（`?` 结尾或标准查询），不发任何 `=` 写入。

```bash
python scripts/probe_battery.py
```

结果（28 条候选）：

| 指令 | 返回 |
|---|---|
| `AT+CBC` / `AT+CBC?` | `ERROR` |
| `AT*BAT?` / `AT*BATT?` / `AT*BATV?` / `AT*VBAT?` / `AT*BATTERY?` | `ERROR` |
| `AT+BAT?` / `AT+BATT?` | `ERROR` |
| `AT*ADC?` / `AT+ADC?` / `AT*CADC?` / `AT+CADC?` | `ERROR` |
| `AT*VOLT?` / `AT+VOLT?` | `ERROR` |
| `AT*PWR?` / `AT+PWR?` / `AT*POWER?` / `AT+POWER?` | `ERROR` |
| `AT*CHG?` / `AT*CHARGE?` / `AT*TEMP?` | `ERROR` |
| `AT*MRD_BAT?` | `ERROR` |
| `AT+MIFIBAT` / `AT+GETBATVOL` | `+CME ERROR: 4` |
| `AT+CLAC` | `ERROR` |

## 5. 一个值得注意的差别：`ERROR` ≠ `+CME ERROR: 4`

- **裸 `ERROR`** = 解析器不认识这条指令
- **`+CME ERROR: 4`** = "operation not supported"，**指令名认识，功能没实现**

`AT+MIFIBAT` / `AT+GETBATVOL` 返回的是后者，说明固件里注册过这两个桩函数。理论上工厂模式（`AT*PROD=1`）有可能放开，但属于写操作、且不确定，**没有验证**——这也是这个项目停在这里、转去 Web 接口的原因之一。

## 6. 其它踩过的坑

| 坑 | 现象 | 结论 |
|---|---|---|
| 频段回显格式不符 | `AT*BAND?` 返回 9 个参数（`5,0,129,480,149,0,2,2,0`），而社区工具假设 54 参数 | 解析器会失效，别照抄 |
| 扫频超时 | `AT+COPS=?` 全网扫频 >1s | 任何固定短超时都会误判成"无返回" |
| CS 域 denied | `+CREG: 3,3` | LTE-only 数据终端的正常现象，不是故障 |
| 日志口静默 | COM4 读空后没输出 | 不是口坏了，本来就这样 |

## 7. 工具用法

```bash
python scripts/asr_cli.py ports              # 列出串口并标出 ASR 复合设备
python scripts/asr_cli.py at "AT+CGMR"       # 发一条指令，打印原始返回
python scripts/asr_cli.py at "AT+COPS=?" --wait 8   # 慢指令加大等待
python scripts/asr_cli.py log --port COM4 --seconds 10   # 抓日志
```

`asr_cli.py` 默认用 COM3，换机器或换 USB 口后先用 `ports` 看一眼描述里的 `USB\VID_1286` 再指定 `--port`。
