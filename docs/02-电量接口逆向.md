# 02 · 电量接口逆向

AT 口没有电量，那就去找**固件自己的数据出口**。结论：有一个 HTTP 接口，只读、不用登录、返回 22 个字段，其中 4 个与电池有关。

## 1. 怎么找到的

1. 设备管理页 `http://192.168.1.1` 是个登录页，标题 `LTE Wireless Router`。
2. 页面引用了 `/js/base.js`（299 KB）——**前端代码里写着所有接口地址**。
3. 在 `base.js` 里搜 `battery`：

```js
var level = json.battery_percent;
if (json.battery_charge == "1") { ... "充电中" }
// 还有一行被注释掉的： //alert(Battery_voltage);
```

那个被注释的 `Battery_voltage` 说明**早期版本暴露过电压，现在不输出了**。

4. 顺着 `json` 的来源找请求：

```js
url = host + 'xml_action.cgi?method=get&module=duster&file=' + jsonName + Date.parse(new Date());
```

`method=get&module=duster` —— 这是 Marvell/ASR 血统的 **duster** 框架，页面名就是 `json_<名字>`。

## 2. 接口规格

```http
GET http://192.168.1.1/xml_action.cgi?method=get&module=duster&file=json_status_info
```

- **无需认证**：不传 Cookie、不传 Token、不需要 `Authorization`，响应头带 `Access-Control-Allow-Origin: *`
- 末尾的毫秒时间戳（`Date.parse`）是前端为了绕缓存加的，**可以省略**
- 返回 `application/json`

## 3. `json_status_info` 的 22 个字段

**全部是字符串类型**，需要 `int()` 转换并做异常兜底。

| 字段 | 含义 |
|---|---|
| `battery_percent` | 电量百分比 `"0"`–`"100"` |
| `battery_charge` | `0` 未充电 / `1` 充电中 / `2`、`3` 已充满 |
| `battery_charging` | `1` = 正在充 |
| `battery_connect` | `1` = 电池在位 |
| `rssi` | 信号强度（如 `-82`） |
| `signal_quality` / `total_signal_quality` | 信号格 |
| `pc_valid` | 是否插着电脑 |
| `wifi_clients_num` | 连着几个客户端 |
| `run_seconds` | 运行秒数 |
| `tx_byte_all` / `rx_byte_all` | 累计流量 |
| `tx_speed` / `rx_speed` / `tx_max_speed` / `rx_max_speed` | 瞬时/峰值速率 |
| `sys_mode` / `roaming` | 网络制式、漫游 |
| `new_sms_num` / `unread_long` | 短信 |
| `password_status` / `login_status` | 管理页状态 |

## 4. 另外两个有用的接口

```bash
# 完整 LTE 工程参数：band / pci / earfcn / rsrp / rsrq / sinr / cqi / ECGI
curl "http://192.168.1.1/xml_action.cgi?method=get&module=duster&file=json_engineering_info"

# 设备身份：IMEI / IMSI / ICCID / MAC / 软件版本
curl "http://192.168.1.1/xml_action.cgi?method=get&module=duster&file=json_homepage_info"
```

`json_engineering_info` 对调信号问题很有用，字段比 AT 口的 `AT*CELL?` 全得多。

## 5. 电压：确实是拿不到

把 duster 的 16 个接口全扫了一遍：

```
homepage_info  device_management_info  firmware_info  custom_fw_info
wan_info  mss_status  band_get  login_info  account_management_info
dhcp_info  wlan_info  wan_pdp_context_info  device_info  status_info
engineering_info  battery_info
```

**没有任何 `voltage` / `ADC` / `mV` 字段**。`json_battery_info` 这个名字看着像，实际返回的是 `{"code":..}` 之类，不含数据。

双路径穷举结论：

| 路径 | 结果 |
|---|---|
| AT 层 28 条候选指令 | 全失败 |
| Web 层 16 个接口 | 只有百分比，无电压 |

所以阈值判断只能基于百分比。对"低电量提醒"这个目标来说，百分比（1% 粒度）完全够用。

## 6. 失败语义（很重要）

写监控时最容易犯的错：**请求失败就当 0%**，然后疯狂报警或者显示"电量耗尽"。

正确做法：

| 情况 | 处理 |
|---|---|
| 超时 / 连不上 | 保留上一次的有效电量，只把"在线"置 false |
| 返回不是 JSON | 同上，记录错误原因 |
| `battery_percent` 非数字或超 0–100 | 判为无效读数 |
| `battery_percent` 为 `0` **且** `battery_connect` 为 `0` | 判为无效（占位值，不是真的耗尽） |

代码里用 `Option<u8>` / `None` 表达"未知"，**不要用 `unwrap_or(0)`**。

## 7. 复现

```bash
curl -s "http://192.168.1.1/xml_action.cgi?method=get&module=duster&file=json_status_info" | python -m json.tool
```

如果 `192.168.1.1` 不通，先看 RNDIS 网卡拿到的网关地址——插拔 USB 后网段可能变。
