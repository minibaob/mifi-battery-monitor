# 04 · 原生集成进岛仔 Daozai

目标：把随身 WiFi 的电量做成岛仔里的一页，而不是外挂一个窗口。

岛仔是 MIT 开源的 Rust + egui 桌面端（[Renly1994/xiaotang-daozai](https://github.com/Renly1994/xiaotang-daozai)），本文基于 **v0.6.64**。

## 1. 先说结论：没有插件机制

想把功能做成"装个包就多一页"，这条路在岛仔上不存在。四条独立证据：

| 检查 | 结果 |
|---|---|
| 插件框架 | 520 个源文件里，`plugin` 只命中 WorkBuddy 的 API 路径；页面是 `PAGE_NAMES: [&str; 9]` 数组 + `render_page()` 里的 `match`，**编译期写死** |
| 脚本 / HTML 注入 | egui 是即时模式 GUI，没有 WebView、没有 DOM、没有 JS 运行时 |
| 外部数据入口 | 没有 webhook、没有配置文件监听、没有通用本地 HTTP 或命名管道（唯一的 `TcpListener` 在 `calendar.rs`，只服务 CalDAV 发现） |
| 扩展文档 | `docs/` 只有 USAGE / PRIVACY / DEPENDENCIES / ai-quota-adapters |

所以只能改源码。为了"官方更新后不丢"，改动做成**可重放的补丁**（见第 6 节）。

## 2. 集成方式：新增第 10 页

常驻条（`bar_layout.rs`）的槽宽只有 14–44px，塞不下"百分比 + 进度条 + 状态 + 更新时间"；硬塞还要改 `WIDTHS`、`DEFAULT_ORDER`、`valid_order` 三处强耦合，并且旧配置只有 6 项会回退。

页面方案更干净：新页索引 **9 = "随身 WiFi"**，排在"天气"后面。

页面布局：

```
┌─────────────────────────────────┐
│  随身 WiFi · 波导 M03X      ● 充电中 │
│  86%                            │
│  ████████████████░░░░           │
│  21:05 更新            信号 5/5   │
└─────────────────────────────────┘
```

四种状态：**在线正常 / 在线充电 / 离线 / 未启用**。灰色只表示"没数据"，绝不显示成 0%。

## 3. 改动清单

| 文件 | 类型 | 内容 |
|---|---|---|
| `src/mifi.rs` | 新增 | 配置、快照、提醒状态机、HTTP 采样、PushPlus、后台线程 + 7 个单测 |
| `src/mifi_ui.rs` | 新增 | 页面渲染、设置表单、每帧泵 |
| `src/app.rs` | 改 | `PAGE_NAMES` 9→10、`PAGE_SETTINGS_TABS`、`dots: [Spring; 10]`、`App.mifi` 字段、`render_page` 分支、每帧 `pump` 与提醒联动 |
| `src/model.rs` | 改 | `visible_pages`/`page_order` 扩到 10 项、7 个 `mifi_*` 配置（默认/解析/序列化）、旧配置兼容 |
| `src/extras.rs` | 改 | 设置窗口新增 tab 13、页面描述数组补第 10 项 |
| `src/ui_tests.rs` | 改 | 页面数相关断言同步到 10 |
| `docs/mifi-battery.md` | 新增 | 上游视角的功能说明与构建说明 |

**不碰**：`main.rs::read_power()`（本机电量）、`bar_layout.rs`（常驻条槽位）。两种电量完全独立。

## 4. 三个必须注意的兼容性细节

### 4.1 页面数组从 9 变 10，是编译期错误级的改动

`visible_pages: [bool; 9]`、`page_order: [usize; 9]`、`PAGE_NAMES: [&str; 9]`、`PAGE_SETTINGS_TABS`、`dots: [Spring; 9]` 五处定长数组，漏一处就编译不过（这反而是好事，编译器会逐个指出来）。

### 4.2 旧配置必须能升级

`settings.txt` 里 `visible_pages=111111111`（9 位）、`page_order=0,1,...,8`（9 项）。解析时要：

- `visible_pages`：不足位时补到末尾，补的值取"已有位里有没有 1"
- `page_order`：**必须是 `0..len` 的一个完整排列**才接受，缺的页按索引补到末尾，重复/乱序缺项整条丢弃回落默认

第二条特别容易写松。第一版实现只做了"缺啥补啥"，结果 `8,1,2,3,4,5,6,7` 这种缺 0 的非法值被当成旧配置接受了 —— 上游的测试直接抓到了。

### 4.3 第 10 页要有设置页描述

`extras.rs` 的"页面管理"里有个 `descriptions` 数组，9 项。加了页面不补这一项，打开设置会 **index out of bounds panic**。这个也是测试抓到的。

## 5. 构建：没有 MSVC 怎么编

上游是 `x86_64-pc-windows-msvc` + 静态 CRT，但开发机没有 MSVC、没有 Windows SDK，当前账户也不是管理员，装不了 VS Build Tools。最后从零搭了一条 gnu 链：

| 环节 | 做法 |
|---|---|
| Rust | `rustup` 有硬链接 bug（`rust-analyzer.exe` 已存在，os error 183）→ 直接从 USTC 镜像下 `rustc`/`cargo`/`rust-std` 的 tar.xz 手工拼装（1.100.0，**gnu host**） |
| C 链接器 | MSYS2（免管理员）→ `pacman -S mingw-w64-x86_64-gcc` |
| 缺的库 | mingw 没有 `winsqlite3` 导入库 → `objdump -p` 读系统 DLL 导出表 + `dlltool` 现场生成 |
| 图标 | `build.rs` 找不到 `rc.exe` 会跳过资源 → 用 mingw 的 `windres` 手工编译 + `-C link-arg` 注入 |
| crates 镜像 | `rsproxy.cn` sparse index |

关键点：**必须用 gnu host**。构建脚本（build script）永远是按 host 编译的，msvc host + gnu target 的组合依然要 MSVC 链接器。

```bash
export PATH="/path/to/mingw64/bin:/path/to/rust-gnu/bin:$PATH"
export CARGO_HOME=/path/to/cargo
cargo test --lib                      # 单测

# 带图标的发布构建
windres -c 65001 -i app.rc -o app_res.o -O coff
RUSTFLAGS="-C target-feature=+crt-static" \
  cargo rustc --release --bin daozai -- -C link-arg=$PWD/app_res.o
```

## 6. 图标坑：windres 不认 PNG 压缩的 ico

`assets/daozai.ico` 的 7 张图全是 **PNG 压缩格式**（Vista+）。windres 会把 PNG 字节原样写进 `RT_ICON`，Windows 资源管理器和 `LoadImageW` 都可能渲染成空白方块。

解法：先用 Pillow 转成传统 BMP/DIB 条目再编译。

```python
from PIL import Image
Image.open('assets/daozai.ico').save('app_local.ico', format='ICO',
    sizes=[(16,16),(24,24),(32,32),(48,48),(64,64),(128,128),(256,256)],
    bitmap_format='bmp')
```

校验：解析 exe 的 `.rsrc`，每个 `RT_ICON` 数据应以 `28 00 00 00`（BITMAPINFOHEADER）开头，而不是 `89 50 4E 47`（PNG 签名）。

如果图标换了但桌面还显示白的：那是 **Explorer 的 iconcache**。删 `%LOCALAPPDATA%\IconCache.db` 与 `%LOCALAPPDATA%\Microsoft\Windows\Explorer\iconcache*.db`，重启 explorer.exe；或者干脆删掉快捷方式重新"发送到桌面"。

## 7. 测试对比（关键：别破坏原功能）

| | 通过 | 失败 |
|---|---|---|
| 上游未改动（基线） | 1085 | 7 |
| 加功能后 | 1091 | 8 |

- 多出的 7 个通过 = 新增的 mifi 单测
- 多出的 1 个失败是 `quota::doubao::encrypted_storage...`，**并行跑时抢 Windows 凭据库**导致的偶发（单独跑和串行跑都通过），与本改动无关
- 基线那 7 个失败全是环境相关：messenger/QQ/微信原生窗口测试、doubao keyring、`tray::icon_resource_is_embedded`（缺 `rc.exe`）

## 8. 官方更新后怎么跟进

改动以补丁形式保存在 `patches/`，用一个 tag 标记"基于哪一版上游"：

```bash
git fetch upstream main
git rebase --onto upstream/main mifi-base feature/mifi-battery
git tag -f mifi-base upstream/main
```

冲突基本只会出现在 `app.rs` 的 `PAGE_NAMES`、`model.rs` 的配置段、`extras.rs` 的 tab 表、`ui_tests.rs` 的页面数断言——都是上面第 4 节说过的定长数组。

更新器是**纯手动**的（`updates.rs` 里 `check()` 只在"检查更新"按钮点击时调用），没有后台静默更新，所以只要不点"下载并安装"，本地改的版本不会被覆盖。
